# Deploying to shared hosting

The application requires PHP 8.2 or newer, MySQL/MariaDB, Apache rewrite
support, and the PHP extensions listed in `README.md`.

## File manifest

### Required application source

These files and directories must remain in the repository and be uploaded:

```text
.htaccess
app/
legacy/application/controllers/
legacy/application/core/
legacy/application/helpers/
legacy/application/language/
legacy/application/libraries/
legacy/application/models/
legacy/application/views/
public/.htaccess
public/index.php
public/theme/
composer.json
composer.lock
writable/ directory skeleton
```

The `legacy/` directory is required. CodeIgniter 4 routes every web request
through `App\Controllers\Legacy`, which loads the POS controllers, models,
views, helpers, language files, and PDF integrations from
`legacy/application/`.

The following font is also required because purchase PDF generation embeds it
directly:

```text
legacy/application/libraries/tcpdf/fonts/NotoSerifBengali-Regular.ttf
```

### Required on hosting but not committed

These are required at runtime but must be created or installed separately:

```text
.env                    server URL and database credentials
vendor/                 generated by Composer
writable/cache/
writable/logs/
writable/session/
writable/uploads/
public/uploads/         current business images and uploaded files
MySQL/MariaDB database
```

Run `composer install --no-dev --optimize-autoloader` to create `vendor/`. If
the host cannot run Composer, generate `vendor/` locally and upload it
separately. Copy current `public/uploads/` business media to hosting separately
when the imported database refers to those files.

### Not required to serve the web application

These are development, documentation, local-machine, or generated files:

```text
tests/
build/
tmp/
phpunit.dist.xml
php-ci4.ini
start-pos.cmd
MIGRATION.md
README.md
DEPLOY_SHARED_HOSTING.md
*.sql
*.zip
*.tar
*.gz
runtime logs, sessions, caches, debugbar output, and imported CSV copies
```

Documentation and tests may stay in GitHub because they are small and useful,
but they do not need to be uploaded to production hosting. Never upload a real
`.env`, database dump, customer export, or password-containing backup to a
public repository.

## Recommended layout

Keep the application outside the public web directory and set the domain's
document root to the project's `public` directory:

```text
/home/account/pos-ci4/
    app/
    legacy/
    vendor/
    writable/
    public/        <- domain document root
```

In cPanel this is normally configured under **Domains** by setting the
document root to:

```text
/home/account/pos-ci4/public
```

This is the safest layout because `.env`, application code, Composer files,
and runtime data cannot be requested from the web.

## Fallback layout

If the host does not allow changing the document root, upload the complete
project into `public_html`. The root `.htaccess` included in this repository
blocks private directories and internally serves `public/`:

```text
/home/account/public_html/
    .htaccess
    app/
    legacy/
    public/
    vendor/
    writable/
```

The fallback requires Apache `mod_rewrite` and permission to use `.htaccess`.
If the host returns error 500 for `Options -Indexes`, remove only that line
from the root and `public/.htaccess` files.

## Installation

Using the cPanel Terminal or SSH:

```bash
git clone YOUR_GITHUB_REPOSITORY pos-ci4
cd pos-ci4
composer install --no-dev --optimize-autoloader
cp .env.production.example .env
```

If the host has no Terminal/SSH, run the Composer command locally and upload
the resulting `vendor` directory with the rest of the project.

Edit `.env` on the server:

```ini
CI_ENVIRONMENT = production
app.baseURL = 'https://your-domain.example/'

database.default.hostname = localhost
database.default.database = hosting_account_pos
database.default.username = hosting_account_posuser
database.default.password = 'your-database-password'
database.default.DBDriver = MySQLi
database.default.port = 3306
```

Do not commit or upload the real `.env` to GitHub.

## Database

1. Export the local `pos` database using phpMyAdmin.
2. Create a database and database user in the hosting control panel.
3. Grant the user all privileges on that database.
4. Import the SQL privately through the hosting phpMyAdmin.
5. Put the hosting database name, user, and password in the server `.env`.

Database dumps may contain customer data and password hashes. Never put them
in a public GitHub repository.

## Permissions

The web-server account must be able to write to:

```text
writable/
public/uploads/
```

Use directory permission `775` when supported. Avoid `777` unless the hosting
provider explicitly requires it.

## Production checks

Run these from the project directory when Terminal/SSH is available:

```bash
php spark phpini:check
php spark cache:clear
php spark routes
```

Then verify:

1. The HTTPS login page loads without `/public` or `/index.php` in the URL.
2. Superadmin can log in.
3. Dashboard assets and uploaded images load.
4. Logout returns to the login page.
5. `writable/logs/` contains no new `CRITICAL` errors.
